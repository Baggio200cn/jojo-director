# GRAPH 数据契约律

> **节点之间只认数据契约，不认名字、不认顺序；写操作必须合并与验证，单一事实必须只有一个源头。**

白话：画布产线是一张图，几十个节点互为上下游。GRAPH 律管的是节点之间
"凭什么信任对方"——答案是契约（约定好的字段和语义），
而不是"我记得那个节点叫什么/在哪个位置"。

## 条款

**G1 失败合并，不许覆盖**
节点执行失败时，错误信息**合并**进 outputs，绝不整体覆盖。
outputs 里可能躺着用户上传的素材、上一次成功的资产——一次失败把它们抹掉，
等于让用户为系统的错误买单。写库的默认动作是 merge，覆盖必须是显式决定。

**G2 API 读写对称**
PATCH 能写的字段，GET 必须能读回；PATCH 写完的返回结构必须与 GET 一致。
"写进去了但读不出来/读出来长得不一样"会让上层逻辑静默失效——
最危险的 bug 是不报错的 bug。

**G3 单一事实源（同文原则）**
同一份信息在图里只允许有一个权威源头，所有消费方从源头取。
实证：解说词的源头是 script 节点的 narration 字段——字幕（合成期 SRT）和
配音（TTS 自动取词）都从它取，改词只改一处；片内不再烧任何文字卡
（单一字幕轨），杜绝两套文字互相打架。

**G4 按图遍历，禁按名索引**
下游找上游、驱动器找目标，一律沿边遍历 + 按 type/status 过滤
（"本项目内 succeeded 的 tts 节点"），禁止硬编码节点标题或假设创建顺序。
名字是给人看的展示层，图才是机器可依赖的结构层。

**G5 契约进提示词**
Agent 建节点也是图的写入方，同样受契约约束：每种节点的 inputs 字段、
取值范围、自动行为（"text 可空=自动取项目脚本"）写进 agent_system.md，
模型和人类读同一份契约。新增节点类型时，执行器、限额表、前端表单、
Agent 契约四处同步登记，缺一处就是幽灵功能。

## 实证案例（迈克尔逊验收九缺陷中的 4 个）

| 缺陷 | 现象 | 修法（条款） |
|------|------|--------------|
| ③ 失败覆盖 outputs | 增强节点失败，把用户刚上传的素材引用抹掉了 | 失败合并不覆盖（G1） |
| ⑥ PATCH 静默丢 outputs | 路由裁定写进 outputs 被接口忽略，裁定"看起来生效了"实际没存 | PATCH 支持 outputs（G2） |
| ⑧ PATCH/GET 返回不一致 | PATCH 返回 raw 字符串，驱动器按 GET 结构解析崩溃 | 驱动器容错 + API 待统一（G2） |
| ⑦ 按假设节点名跑批 | 节点改名后驱动器找不到目标空转 | 动态遍历图（G4，与 LOOP L5 共享） |

另：TTS 上线（2026-08-01）新增契约两条——**配音字幕同文**（G3 的落地：
配音与 SRT 同取 script.narration，浓缩解说时原文存 narration_full 可回滚）；
**拼接自动混音**（compose 沿图发现本项目 succeeded 的 tts 节点，G4 的落地）。

## 落地检查清单

- [ ] 所有写 outputs 的代码路径：确认是 merge 语义，失败分支尤其要查
- [ ] 新增/修改 API：PATCH 完立刻 GET 验证读回一致
- [ ] 出现"同一段文字/数值存两处"时：立刻收敛为单一源+消费方引用
- [ ] 新节点类型上线四件套：执行器注册、auth 限额、前端表单、agent_system.md 契约
- [ ] 验收方法：改掉所有节点标题再跑一遍产线，任何环节失灵即违反 G4
