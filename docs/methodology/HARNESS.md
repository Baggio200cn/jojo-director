# HARNESS 环境保障律

> **环境即代码：运行环境的每一个假设——依赖、模型、凭证、进程、网络——都必须显式声明、随部署交付、可被验证。**

白话：代码在本机跑通只证明"本机环境恰好满足了它的隐藏假设"。HARNESS 律管的是
把这些隐藏假设一条条挖出来写进仓库，让"部署到云端"变成机械动作而不是二次开发。
（HARNESS 原意是马具/试验台架——把烈马套进车辕的那套装备。）

## 条款

**H1 依赖清单即真相**
运行所需的每个包都写进 requirements.txt / package.json。判据不是"import 没报错"，
而是"新开一台裸机，按清单装完就能跑"。本机 pip 里装过什么不算数。

**H2 模型与大文件随部署直推**
运行时下载（HuggingFace、CDN）在生产环境是不可靠假设：服务器到外网可能
401/超时/被墙。Whisper 等模型文件随部署 scp 直推，代码用环境变量
（WHISPER_MODEL_DIR）指向本地目录，下载只是开发期的便利，不是生产依赖。

**H3 凭证只住 .env**
API key、TTS 凭证、管理员密码只放 .env（gitignore 保护），代码里只有
os.getenv 和"缺了怎么提示用户去哪里配"。部署清单里必须有"云端 .env 补齐"这一步——
本地 .env 不会自动跟着代码走，这是最常见的"本地好好的，云上 500"。

**H4 事件循环是稀缺资源**
异步服务里跑 CPU/子进程重活（ffmpeg、模型推理）必须 asyncio.to_thread 或进程池。
一个同步阻塞调用会饿死整个事件循环——表现为"全站卡死"，
而根因藏在某个不起眼的执行器里。

**H5 进程模型要驯服**
生产不用 --reload（文件变动导致意外重启，杀掉进行中的任务）；
Windows 下重启服务用进程树整杀（taskkill //T），否则孤儿 uvicorn 占着端口装活着。
部署脚本里"重启+健康检查"必须是一个动作：restart && sleep && curl /api/health。

**H6 部署走文件直推，不赌网络**
云端从 GitHub pull 依赖"服务器到 GitHub 的网络"，实测经常性失败。
标准动作：本机构建（npm run build）→ scp 直推产物与源码 → 重启 → 健康检查。
新旧版本用 dist_new/dist_old 原子切换，失败可回滚。

## 实证案例（迈克尔逊验收九缺陷中的 3 个）

| 缺陷 | 现象 | 修法（条款） |
|------|------|--------------|
| ② ffmpeg 饿死事件循环 | 拼接一开跑，整个后端所有接口无响应 | 重活线程化 asyncio.to_thread（H4） |
| ④ 云端 HF 下载 401 | Whisper 模型运行时下载失败，R4 转写全线不可用 | 模型随部署直推 + WHISPER_MODEL_DIR（H2） |
| ⑤ 云端缺 matplotlib | 代码渲染本机正常、云端 ImportError | requirements 补齐，环境即代码（H1） |

另：TTS 上线（2026-08-01）完整走了一遍 H3——凭证本地 .env 配好后，
部署清单显式包含"云端 .env 追加 TTS_APPID/TTS_TOKEN/TTS_VOICE"，一次到位。

## 落地检查清单

- [ ] 新依赖：装完立刻写 requirements.txt，部署时云端 pip install -r 验证
- [ ] 新模型/大文件：进部署脚本的 scp 清单，代码读环境变量定位
- [ ] 新凭证：.env 三件套——本地配、云端配、缺失时的引导文案
- [ ] 新执行器：凡调子进程/重计算，必须 to_thread
- [ ] 每次部署以 curl /api/health 收尾，失败即回滚 dist_old
- [ ] 验收方法：模拟裸机（新 venv/新目录）按 README 部署一遍，不允许任何"我记得还要装个啥"
