# JOJO Director 产线方法论

AI 内容产线（多节点画布 + 模型编排 + 云端部署）在真实生产中反复踩到的坑，
沉淀为三条工程定律。每条定律都以 2026-07-31 迈克尔逊干涉仪全流程验收暴露的
**九个真实缺陷**为实证案例——不是理论推演，是修完 bug 之后的归纳。

| 定律 | 一句话 | 管什么 |
|------|--------|--------|
| [LOOP 执行循环律](LOOP.md) | 一切超过 60 秒的工作必须后台化，一切跨网调用必须假设会断 | 任务的生命周期：怎么发起、怎么等、断了怎么办 |
| [HARNESS 环境保障律](HARNESS.md) | 环境即代码：运行环境的每一个假设都必须显式声明、随部署交付 | 代码跑在哪：依赖、模型、凭证、进程模型 |
| [GRAPH 数据契约律](GRAPH.md) | 节点之间只认数据契约，不认名字、不认顺序、不许覆盖 | 节点间怎么传数据：读写规则、失败语义、一致性 |

三条定律分别对应产线故障的三个来源：**时间**（LOOP：慢与断）、
**空间**（HARNESS：本机与云端不一样）、**协作**（GRAPH：上下游互相踩）。

## 教材用途

本目录同时是《AI 内容生产线规程》教材章节的素材来源。每篇的结构固定为：
定律陈述 → 白话解释 → 条款 → 实证案例（真实缺陷+修法）→ 落地检查清单，
可直接改写为实训指导书的"产线规程"章节。
